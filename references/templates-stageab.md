## G. Stage A — demo 任务书

与实现任务书规则相反，**不要复用实现任务书的语气**。

```markdown
## D-ORDER-CENTER 订单中心 · 方案 [A/B/C]

**场景**：运营每天处理 200~800 单，需要按状态筛选、批量定位异常单、给订单加内部备注。

**探索方向**（本份方案要押的方向，与其他方案刻意不同）：
- 方案 A：表格为主 + 行内操作
- 方案 B：状态看板 + 拖拽
- 方案 C：表格 + 右侧抽屉详情
> 派发时给每个 agent 不同的方向，否则产出会趋同，比稿失去意义。
>
> **Pre-flight 成本闸门（三问，任一为否即 ABORT，借 adhd）**：① 问题开放（没有已知唯一正确答案）？② 赌注够高（选错代价大）？③ 表述开放（不是引导性问题）？一轮比稿 ≈ N 次 agent 调用、5~10× 单次成本。
>
> **认知框架畸变（防同质化，借 adhd）**：每份方案除方向外再分配一个刻意畸变的认知框架（如「监管者视角」「生物学/演化视角」「speedrunner 视角」「10 岁用户视角」「$0 预算视角」），零共享上下文发散；**前三个显而易见的答案被禁止**。分支互相看见即互相锚定，方法退化为更宽的单线程思维。
>
> **两相硬分离（借 adhd）**：发散阶段禁止任何评价（critic 会扼杀 generator）；全部产出到位后才开评审相——每份方案按 novelty / viability / fit 三轴打分（各 0-10）+ trap 标记（隐藏成本 / 虚假经济 / 过早抽象），聚类剪枝后深化幸存者。

**必须真**：
- 只能用 @/theme 里的 design token（色/间距/字号/断点）
- 字段命名遵循 docs/plan/field-draft.md（第一版可为空，由你提议命名）
- 业务约束：客服角色不可见「成本价」列；closed 状态不可编辑备注
- 数据形状要能压测：至少塞入超长订单号、5 行地址、emoji、null 字段、0 条、200 条

**明确放开（不用管）**：
- 接口写死本地 JSON
- 不写测试、不加类型注解、不接真路由、不管状态管理方案
- 可以新增依赖

**禁止**：提交到主干目录 src/modules/；修改 src/components/ 下公共组件

**产出（四件，缺一不算完成）**：
1. 可点击页面（本地能起即可）
2. **假设清单** — 你替需求方做的每一个无声决定（分页大小/排序默认/空值显示/截断策略/时区/金额单位…）
3. **字段需求表** — 界面每个数据项：名称 / 类型 / 可否空 / 来源猜测 / 是否已确认
4. **我没能实现的状态** — 你知道应该有但没做的态（空态？加载失败？无权限？）

**这一阶段的门禁**：不是构建绿，而是「外部走查能否收敛 + 字段需求表能否映射到数据模型」。
```

## H. Stage A — 外部走查记录（收敛用，替代内部评审）

Design Sprint 的 "test" 环节搬到工程流里，最小可用版本：

```markdown
| 人次 | 角色 | 任务 | 是否完成 | 卡在哪 | 属于哪类反馈 |
|---|---|---|---|---|---|
| 1 | 运营-李 | 找到昨天未支付的单并加备注 | 部分 | 筛选项没有「昨天」快捷 | 语义 |
| 2 | 运营-王 | 同上 | 否 | 在 B 方案里没找到备注入口 | 语义（致命） |
| 3 | 客服-张 | 查看某单成本价 | 是 | — | — |
| 4 | 运营-李 | 处理一张退货异常单 | 否 | 异常单混在列表里无法定位 | 语义 |
| 5 | 运营-赵 | 批量导出前先核对数量 | 部分 | 统计条数字与筛选结果不一致 | 数据 |

反馈分类计数：语义 4 / 审美 1  → 语义仍占多数，**继续下一轮**
若反转（审美 > 50%）→ 冻结，进 Stage B
```

**分类是这张表的价值所在**：语义类反馈指向契约缺口，审美类指向偏好。混淆两者会导致无限改稿——审美永远改不完。

## I. Stage B — 交互分析任务书（只读，汇总式并行）

```markdown
## S-PERM 订单列表 · 权限与可达性扫描

**输入（只读，禁止修改任何文件）**：
- demo 目录 prototype/order-center/plan-A/
- docs/plan/field-draft.md
- 上一轮的假设清单

**产出**：
1. 状态机：节点 / 边 / 触发条件 / 可见反馈
   必须显式回答：有无死路、并发触发走哪条边、失败后表单数据保不保、乐观更新回滚路径
2. 交互矩阵：元素 × 事件 × 状态变化 × 可见反馈 × 埋点 key
   未定义项标 TBD，并必须归入两类之一：DATA-NEEDED / DECISION-NEEDED
3. 异常清单：每条给「复现路径 + 当前表现 + 期望表现 + 严重度」
4. 与既有页面的不一致点

**本维度具体扫描项**：
- 无权限：列隐藏 还是 整页 403？两者在不同角色下的表现
- 键盘：tab 顺序、抽屉打开后焦点是否落入、关闭后是否归位到触发元素
- aria：状态变化的播报区域、表格与操作按钮的关联标注
- 命中区尺寸（触屏 ≥44px）

**禁止**：提出视觉改版（那是 Stage A 的事，此处只查可达性与语义）
**退出标准**：每条 TBD 都已归类；「先这么做后面再定」这一类不允许存在
```

扫描维度另发 5 份同构任务书：异常态穷举 / 断点适配 / 反馈时机 / 一致性 / 性能感知。同一份 demo，六个 agent，产出互不重叠——这是「汇总式合并」，并行度可以放到 6。

## K. 决策日志（跨 agent 传递决定，缝合式并行的必需品）

并行 agent 无法共享完整 trace，所以用「已固化的决定 + 各自上报的决定」近似。

```markdown
# decisions.log（Coordinator 维护，每轮派发给所有 agent）

## 已冻结（来自契约，视为公理）
D-001 金额单位：分（int），前端格式化 — 2026-10-14 CR-002
D-002 时间：存 UTC，传输 ISO8601 带 Z，前端本地化显示 — 走查拍板
D-003 pendingCount：后端聚合 — Stage B 拍板，数据量级 >10 万
D-004 分页：cursor，limit 默认 20 上限 100 — 契约 v1

## 本轮新增（agent 上报，待裁决）
D-107 f1：抽屉宽度采用 480px（tokens 未定义该尺寸）→ 裁决：纳入 tokens
D-108 f2：未知 status 值降级为 'pending' → 裁决：**拒绝**，应显式报错（掩盖脏数据）
D-109 f3：备注编辑用 PUT 而非 PATCH → 裁决：采纳，但契约补记语义为全量替换

## 冲突已解决
D-105 vs D-106：两处对空值显示不一致（— vs 空白）→ 统一为 —
```

派发新任务时，把这个文件连同契约一起给。**这是目前唯一可行的「让并行 agent 看到彼此决定」的工程办法**——比让 agent 互相对话可靠得多。

## L. 抽象候选清单（Phase 4 Integrator 必交付物）

并行开发的默认结局是各写一份相似实现（GitClear 数据里代表重构的移动行从约 25% 掉到不足 10%）。不登记就永远不收敛。

```markdown
| # | 重复项 | 出现位置 | 相似度 | 处理 | 理由 |
|---|---|---|---|---|---|
| 1 | 金额格式化 | f1 list / f3 detail | 高 | **本轮抽取** → utils/money.ts | 仅 2 处且逻辑一致，成本低 |
| 2 | 表格列封装 | f1 / f2 / 报表 agent | 中 | 登记下轮 | 三处列定义差异实质的存在，现在抽会造出带 8 个可选 prop 的怪物 |
| 3 | 错误态组件 | 6 处 | 高 | **本轮抽取** → components/ErrorState | 已超 3 处且行为应完全一致 |
| 4 | 时间筛选器 | 4 处 | 中 | 登记下轮 | 等真接口的时间语义在 Phase 4 确定后再抽 |
```

纪律：**抽取是横切动作，属于串行段，不许在 Phase 3 并行做。** 「本轮抽 / 下轮抽」的判据是相似度与出现次数，不是「顺手」。

## M. 走查反馈分类口径

给 Facilitator 用的统一判读，避免第 H 项表格被写成流水账。

| 类别 | 特征 | 去向 |
|---|---|---|
| **语义** | 找不到功能、结果与预期不符、数据不对、状态缺失 | 必须转成字段需求表 / 状态机条目 |
| **数据** | 空态、超量、精度、时区、单位 | 转数据语义约定 |
| **权限** | 谁能看什么、隐藏还是拒绝 | 转 authz 契约 |
| **审美** | 「不够清爽」「颜色别扭」「间距感觉不对」 | 只进 tokens 层，**不进业务逻辑** |

关键：审美类反馈永远改不完，它只应体现为 token 值的改动。若允许它进业务代码，Stage A 就会失控。
